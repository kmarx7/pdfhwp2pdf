# 제품 요구사항 정의서

기준일: 2026-10-24. 상태: PDF MVP 구현 및 합성 문서 검증. 아래 제품 요구·실문서 품질 관문은 유지하며, 미완료 범위와 실제 구현 증거는 [STAGE2_REPORT](STAGE2_REPORT.md)에서 구분합니다. 사용자의 2단계 지시에 따라 실문서 대신 생성한 PDF로 기본 구현을 검사했습니다. 기술 조사 근거와 한계의 기준 문서는 [CONVERSION_SPEC](CONVERSION_SPEC.md)입니다.

## 1. 목표와 사용자

한국어·영어 업무 문서를 Word에서 수정해야 하는 사용자를 위한 PDF·HWP·HWPX→DOCX 변환 웹앱을 만든다. 편집 가능한 텍스트·문단·Word 표를 우선하며 원본의 페이지 크기, 스타일, 이미지와 배치를 가능한 범위에서 보존한다. 모든 입력에서 원본과 픽셀 단위로 동일한 결과를 보장하지 않는다.

본문을 이미지·윤곽선으로 바꾸거나 페이지 스크린샷 아래에 숨은 텍스트를 넣어 편집 가능성을 충족한 것으로 간주하지 않는다. 문서의 사진·로고 자체는 이미지로 유지할 수 있다.

## 3. 사용자 흐름과 UI

1. 드래그 앤 드롭 또는 파일 선택으로 한 파일 업로드. 허용 확장자, 30 MiB 상한, 현재 엔진 지원 상태를 안내한다.
2. 실제 파일 판별 후 파일 형식, 페이지 수(확인 가능할 때), 글꼴·OCR·제한 안내를 보여준다. HWP의 확정 페이지 수는 파싱만으로 알 수 없으면 `알 수 없음`이다.
3. 변환 모드를 선택한다. `balanced`(기본: 문단·표 유지와 배치 균형), `flow`(문단 흐름 우선, 후속), `layout`(페이지 구분 우선, 후속). 구현·검증된 모드만 활성화한다. layout도 이미지 페이지 방식은 금지한다.
4. 변환 버튼으로 작업 생성. 대기→분석→변환→후처리→검증의 실제 단계를 한국어로 표시한다. 엔진에 세부 진행 콜백이 없으면 무한 진행 표시와 단계만 제공하며 가짜 백분율을 증가시키지 않는다.
5. 성공하면 DOCX 다운로드, 경고와 품질 보고서를 제공한다. 미측정 지표는 `측정 안 됨`으로 표시한다. 실패하면 오류 코드, 한국어 설명, 가능한 다음 조치를 제공한다.
6. 삭제 또는 1시간 만료 안내. 후속 비교 화면은 원본과 DOCX 렌더링을 페이지별로 나란히 보여준다. 미리보기 이미지는 평가용이며 DOCX 생성에 페이지 이미지로 삽입하지 않는다.

모바일 360px부터 데스크톱까지 반응형 레이아웃, 키보드 파일 선택·버튼 조작, 포커스 표시, `aria-live` 상태 안내를 제공한다. 색상만으로 성공·실패를 구별하지 않는다. 외부 CDN 없이 정적 자원을 제공한다. 첫 MVP는 한 번에 한 파일이며 배치 업로드는 후속이다.

## 4. 비기능 요구사항

- 로컬 `127.0.0.1`에만 바인딩하고 외부 서비스로 문서를 전송하지 않는다. 원본 문서를 수정·삭제하지 않는다.
- 업로드 복사본만 작업 루트에서 보관한다. 작업별 경로 격리, 파서 프로세스 분리, ZIP/XML·메모리·시간 상한을 둔다. 파일 수명은 [ARCHITECTURE](ARCHITECTURE.md)의 정책을 따른다.
- Python 3.11 `.venv`를 우선하고 시스템 패키지·글꼴·Office를 자동 설치하지 않는다.
- FastAPI 서버 한 프로세스, 변환 동시 1개, 대기 최대 5개. DB·Redis·Celery 도입 없이 시작한다.
- 문서 내용·사용자 파일명·절대 경로를 서버 로그에 기록하지 않는다. 작업 ID, 오류 코드, 엔진 버전, 소요 시간만 기록한다.
- 성능 목표는 단일 단 10쪽 디지털 PDF 60초 이내, 작업 시간 상한 180초, 자식 작업 메모리 목표 상한 1 GiB이다. 목표는 아직 측정되지 않았으며 기기·샘플·버전을 보고서에 명시한다.

## 5. 개발 단계와 관문

| 단계 | 작업 범위 | 완료 기준 및 다음 단계 인계 |
| --- | --- | --- |
| 1 조사·설계 | 여섯 문서, 후보 조사, 환경 확인 | 이번 산출물 작성, 검증/미검증 구분; 앱 구현 없음 |
| 2 PDF 수직 구현 | 환경 lock, 파일 판별, 제한 업로드, 작업 실행, PDF 후보, 후처리·구조 검증, 한국어 UI, 다운로드·삭제 | TEST_PLAN의 단계 2 필수 테스트 통과, 6개 PDF 기준 문서 확보·평가, Word 편집 확인; 실제 지원 범위와 버전 기록 |
| 3 PDF 품질 개선·비교 | 표·다단·스타일·반복 머리말, DOCX 렌더링 비교 | 회귀 코퍼스 지표 충족, 미리보기 렌더러/글꼴 환경 고정 |

| 5 HWP 지원 판단 | ONLYOFFICE 또는 Java 파서 경로, 필요 시 HWP→HWPX 경로 비교 | 최소 5개 HWP v5 실문서, 설치·arm64/Linux·라이선스·품질 확인; 불충족이면 비활성 유지와 근거 기록 |
| 6 OCR | Tesseract `kor+eng`, 페이지별 OCR, 표 구조 별도 복원 | 최소 5개 스캔/혼합 문서, OCR 전용 기준 통과; OCR 결과 편집 가능성 확인 |
| 7 배포 | Linux/Docker, 리소스 격리, 외부 공개 시 인증·접근제어·보존 정책 | linux/arm64·amd64 별 검증; 배포 방식·라이선스 검토 후 공개 |

단계 4·5의 조사 실험은 앞당길 수 있으나 검증 없이 UI 지원 플래그를 켜지 않는다. HWP·HWPX가 미지원인 PDF MVP를 통합 변환 제품 완성으로 표현하지 않는다.

## 6. 제외 범위와 미결정 사항

초기 범위에서 유료 변환 API, 클라우드 OCR, DB, 계정·결제, 디지털 서명 보존, 암호 해제, 매크로 실행, 수식·차트·OLE 완전 편집을 제외한다. 문서 유출 가능성이 있는 외부 대체 경로는 자동 사용하지 않는다.

미결정: PDF 후보의 정확한 호환 버전 조합, 실제 한국어 글꼴 대체표, 실문서 품질, HWP/HWPX 실행 엔진, ONLYOFFICE의 로컬 자동화 방식·arm64 배포물, DOCX 렌더러 설치 상태, OCR 언어 데이터. 각각 다음 실험의 결과로 결정하며 기능 완료로 표시하지 않는다.
