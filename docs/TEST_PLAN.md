## 2. 입력 corpus와 정답 데이터

초기 필수 PDF 기준군은 최소 6개 실문서다: 한국어 단일 단 1개, 영어 단일 단 1개, 한영 혼합 제목·스타일 문서 1개, 단순 유선 표 1개, 사진/로고 문서 1개, 다페이지·머리말/꼬리말·페이지 크기/방향 변경 문서 1개. 필요한 특징은 문서 간 중복될 수 있지만 개수는 6개 이상이다. 각 문서는 사용권·출처·원본 생성 도구·글꼴·예상 페이지와 지원 특징을 기록한다. 머리말 등 아직 지원하지 않는 특징은 측정·제한사항으로 보고하며 지원 플래그를 켜지 않는다.

추가 탐색군: 다단, 회전, cropbox, 무선·병합·중첩 표, 셀 내 다문단, 도형·수식·각주·세로쓰기·비표준 글꼴, ToUnicode 누락, 100쪽/30 MiB 경계. 겉으로 드러나지 않는 품질 실패를 찾기 위해 성공군에 포함하지 않은 특징도 검토한다.

HWP 단계: 최소 5개 HWP v5 실문서(본문, 표, 이미지, 스타일, 다중 section)를 확보하고 v3·암호·배포용·손상 입력을 별도 검증한다. HWPX 단계도 최소 5개 실문서에 같은 요소와 다양한 namespace/manifest·스타일 참조·이미지 관계를 포함한다. OCR 단계는 한국어, 영어, 한영 혼합, 기울어진 스캔, 디지털/스캔 혼합의 최소 5개를 확보한다.

손상·상한·경로 공격 테스트는 자동 생성한 최소 fixture를 사용한다. 실제 업무 문서 없이 대규모 악성 문서를 수집하지 않는다. 원본은 읽기 전용으로 취급하고 SHA-256을 변환 전후 확인한다. 민감 문서는 git에 추가하지 않는다.

정답은 `expected/<sample_id>.json`에 사람이 확인한 Unicode NFC 본문·문단 경계·읽기 순서·제목 레벨·표 셀 및 span·이미지 목록·페이지/여백·중요 필드와 근거를 저장한다. 기준 PDF·필요한 글꼴 라이선스를 함께 기록한다. 정답은 변환 결과나 같은 파서 출력만 복사해 만들지 않는다. 작은 회귀군과 튜닝에 쓰지 않는 보류군을 나누어 과적합을 확인한다.

## 4. 검증 실행과 보고 형식

구현 후 표준 명령은 `.venv/bin/python -m pytest`이며 파일별 unit/contract/integration 표식을 추가할 수 있다. 실제 브라우저와 Word 편집은 별도 기록한다. 네트워크 없는 CI에서 엔진 통합이 skip되면 별도의 엔진 설치 CI에서 실행해 미검증 상태를 해소한다.

각 결과에 날짜, Git commit(저장소가 있을 때), sample ID/해시, Python·OS·아키텍처·패키지/엔진/렌더러/글꼴 버전, 옵션, 명령, pass/fail/skip 수, 소요 시간/peak RSS, 지표와 실패 위치, 수동 검토자·Word 버전을 남긴다. 테스트 출력은 본문과 사용자 경로를 최소화한다. 미검증을 완료에 포함하지 않는다.

## 5. 단계별 완료 관문

### 1단계: 이번 설계 작업

- 요구한 여섯 한국어 설계 문서가 존재한다.
- 모듈·폴더·클래스·공통 엔진 계약·API·상태·파일 수명·오류 규약을 설명한다.
- PDF/HWP/HWPX 후보의 실제 범위·유지보수·라이선스·Apple Silicon 제약을 공식 근거와 함께 기록한다.
- 품질 평가의 정답·계산식·목표·수동 편집·미측정 정책 및 단계별 로드맵을 남긴다.
- 로컬 확인 결과와 실패·미검증 범위를 정확히 기록한다. 패키지 설치 성공·실문서 품질은 이번 완료 조건으로 주장하지 않는다.

### 2단계: PDF MVP

환경 E01, U01~U04, C01~C02, I01~I08, A01~A02, B01~B02와 해당 PDF 후처리/검증 테스트가 통과해야 한다. U05/I03의 아직 지원하지 않는 확장 요소는 지원 플래그·오류/경고가 정확한지 검증하고 성공 지원으로 보고하지 않는다.

PDF 6개 기준군 중 공개 지원 범위의 문서별 필수 관문과 CONVERSION_SPEC 목표를 충족해야 한다. 지원하지 않는 특징은 명시하고 대응 제한 테스트를 통과해야 한다. 최소 한국어 본문·단순 표·이미지 문서의 Word 편집/저장·재열기를 확인한다. 샘플이나 Word 검증이 없으면 구현은 진행할 수 있지만 **PDF 품질 관문은 미완료**다. 시각 렌더러가 없으면 구조 검증 완료와 시각 평가 미완료를 분리해 표시하며 시각 품질을 보장하지 않는다. P01 성능 측정, 원본 해시 보존, 정리·강제 종료 검증을 완료한다.

### 후속 단계

HWPX/HWP/OCR은 각각의 corpus·플랫폼·편집·품질 관문을 통과한 엔진/요소만 capabilities에 반영한다. Word 수동 검증, 렌더링 비교, Linux/Docker는 해당 단계를 수행한 환경에서 별도 합격 증거를 남긴다. 공개 배포 전 접근 제어·의존성/라이선스·운영 수명 정책을 점검한다.
