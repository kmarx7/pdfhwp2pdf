# 실제 HWP 표 서식 오류 수정

브랜치 `fix/hwp-table-fills`. 사용자 제공 경로의 HWP 5 한 건을 읽기 전용으로 분석했다. 원본 문서·경로·원문·파싱 모델·결과 파일은 git에 포함하지 않는다. 실문서 한 건의 성공을 전체 HWP 품질 보장으로 표현하지 않는다.

## 확인한 원인과 처리

- 사용된 셀 배경 중 한 종류가 `fill_type=4`인 두 색상 선형 그라데이션이었다. 기존 후처리는 이를 거부했다. 이제 끝 색상의 각 RGB 채널 중간값으로 단색을 생성하고, **그라데이션 효과가 사라진다는 경고**를 화면과 품질 보고서에 남긴다. 단색 근사를 원본 그라데이션 보존이라고 표현하지 않는다. 그림·무늬·복합/방사형/다중 색상 채우기는 계속 거부한다.
- 실제 점선(코드 3)과 이중선(코드 8)을 DOCX `dotted`·`double`로 옮긴다. 색상·기존 두께 매핑을 유지한다. 근거: 고정 엔진의 [테두리 매핑](https://github.com/STAIxBWLB/hwp-cli/blob/v1.3.1/crates/hwp-render/src/border.rs), [배경 파서](https://github.com/STAIxBWLB/hwp-cli/blob/v1.3.1/crates/hwp5/src/doc_info.rs).
- 표 2개의 일부 병합 행 전체 너비와 개별 열 합계가 283 HWPUNIT(2.83pt) 달랐다. 제약 그래프에서 개별 열을 우선하는 최소 비용 경로로 경계를 정한다. 경계와 셀 너비 차이가 3pt를 넘으면 거부하고, 0.1pt 초과 정규화는 개수·최대값을 경고한다. 원문·셀 병합·run을 재작성하지 않는다.
- 후처리에서 생긴 너비 조정 경고도 완료 이벤트로 전달하여 UI와 품질 보고서가 일치하게 했다.
- 표 배경·테두리 종류/색상 검증을 추가했다. 원본 모델에서 계산한 근사 배경이 빠지거나 달라져도 성공으로 제공하지 않는다. 전체 표 개수 지표에 중첩 표도 포함한다.

## 검증 결과

`.venv/bin/python -m pytest -q` → **82 passed, 6 warnings in 12.90s**. 실제 합성 HWP의 그라데이션 근사·점선·이중선·화면/보고서 경고 일치, 배경 손실 주입 거부, 2.83pt 정규화·3pt 초과 거부, 미지원 배경 거부 테스트를 추가했다. 기존 PDF/HWP 및 다운로드 폴더 테스트도 통과했다.

사용자 원본으로 로컬 브라우저에서 업로드→변환 성공→DOCX 다운로드를 확인했다. 내려받은 결과는 **31,017 bytes**, 실제 `w:t` 784개, 표 **38개(본문 32 + 중첩 6)**, 섹션 **3개**였다. 원본 표의 행/열·셀 병합, 이미지 목록, 섹션 수·페이지 크기 검증을 통과했다. 문자 다중집합 기반 coverage는 **1.0**이며 읽기 순서나 실제 CER 검증을 뜻하지 않는다. 원본 SHA-256은 작업 전후 같았다.

수정 결과에도 그라데이션 단색 근사와 표 2개의 최대 2.83pt 조정 경고가 있다. 실제 Word 앱 열기·페이지 배치·폰트·쪽 번호 표시·원본과의 시각 비교는 미검증이다. 원본의 모든 서식을 그대로 보존했다고 주장하지 않는다.

API 작업 결과는 기존 1시간 수명 정책을 따른다. 전달용으로 별도 내려받은 `runtime/user-case/converted.docx`와 품질 보고서는 다운로드한 사용자 결과물로 취급하여 수동 삭제 전까지 보관한다. 진단 중간 모델과 원본 경로 참조는 정리한다. 원본 HWP는 삭제하거나 수정하지 않는다.
